Gittydocs includes authoring components directly in `.mdx` pages. **No imports, package installs, or ejection are needed.** Use the component names with their exact capitalization, and put Markdown content between the tags.

| Component | Use it for |
| --- | --- |
| [Code blocks](/components/code-blocks) | Highlighted code with optional filename headers and a copy button. |
| [Steps / Step](/components/steps) | Numbered instructions with optional step titles. |
| [Files / Folder / File](/components/files) | Collapsible file trees with filename-based icons. |
| [Accordions / Accordion](/components/accordion) | Expandable content, with single or multiple items open. |
| [Tabs / Tab](/components/tabs) | Keyboard-accessible alternatives with synchronized selections. |
| [Type Table](/components/type-table) | An API reference from a manually authored property map. |
| [Auto Type Table](/components/auto-type-table) | An API reference generated from TypeScript at build time. |
| [Callouts](/components/callouts) | GitHub-style notes, tips, important details, warnings, and cautions. |

These JSX components belong in `.mdx` files. Ordinary code fences and Markdown callouts also work in `.md` files. Keep blank lines around Markdown paragraphs, lists, and code fences inside a component so they are parsed as Markdown.

## Markdown exports

**Copy page**, its **Copy page as Markdown for LLMs** action, and generated per-page Markdown convert built-in components into portable text:

| Built-in content | Markdown output |
| --- | --- |
| `Steps` / `Step` | Numbered step headings with the step body underneath. A missing title becomes “Step”. |
| `Files` / `Folder` / `File` | Nested lists of filenames, folder names, and file descriptions. |
| `Accordions` / `Accordion` | Headings with each accordion's full body, even if it starts closed. |
| `Tabs` / `Tab` | A heading for each literal tab value and every panel's full content, regardless of browser selection. |
| `TypeTable` | Safe literal property maps become Markdown tables. Dynamic expressions and JSX descriptions are preserved rather than executed. |
| `AutoTypeTable` | A generated Markdown property table with types, defaults, descriptions, and required/deprecated information. |
| Markdown callouts | Original blockquotes and their `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, or `[!CAUTION]` markers. |

This preserves the meaning of a page without requiring an MDX renderer. Custom JSX and imports are preserved rather than stripped or executed. Dynamic component titles or names that cannot be converted safely are left intact too.

**Syntax examples stay examples:** components inside fenced code blocks or inline code are not converted. Fence language and `title` metadata are retained. Always put demonstration source—including custom `export` examples—in a code fence when you want readers to see it rather than run it.

For output paths and **View as Markdown**, see [Page actions and Markdown output](/configuration#page-actions-and-markdown-output).
